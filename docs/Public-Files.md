# Public Files

Shulkr can host a file for you and give you a public link: an image for an announcement, a resource pack, an archive for your players. Anyone with the link can download it, without an account, through the machine's IP address or through the domain configured as **Panel Domain**.

## Publishing a file

Open **Public files** in the main navigation, click **Upload** and choose a file. Files up to 2 GB are accepted. The browser sends them in 32 MB pieces, so a large upload shows its progress and can be cancelled at any time.

Before uploading, pick:

- **Expiration**: 1 hour, 24 hours, 7 days (default), 30 days, or never. An expired file is deleted from the disk within the hour.
- **Download limit** (optional): once reached, the link stops working and the file is deleted. Link previews generated by Discord and other messaging apps count as downloads.

Each file shows its link and its SHA-1, both with a copy button. When a Panel Domain is configured, links use it (with `https` once SSL is enabled). Otherwise they use the address you are currently using to reach the panel.

## Server resource packs

A public file works as the `resource-pack` of a Minecraft server:

```properties
resource-pack=https://panel.example.org/f/<token>
resource-pack-sha1=<the SHA-1 shown next to the link>
```

Files are stored and served byte for byte, never recompressed or rewritten, so the SHA-1 shown in the panel is exactly the one players' clients compute.

To update the pack, use **Replace the file** on the existing file rather than uploading a new one. The link stays the same, only the SHA-1 changes: update `resource-pack-sha1`, restart the server, and clients download the new version because the digest no longer matches their cached copy.

## Managing public files

- **Edit** changes the expiration (counted from now) and the download limit.
- **Generate a new link** replaces the token: the previous link stops working immediately. Use it when a link was posted somewhere it should not have been.
- **Delete** removes the file from the disk and kills the link.

Uploading requires the `shares:files:upload` permission. Editing, replacing, generating a new link and deleting require `shares:files:manage`. Every upload, change and public download is written to the audit log, public downloads with the visitor's IP address.

## Limits

| Setting                                                          | Default                    | Variable                       |
| ---------------------------------------------------------------- | -------------------------- | ------------------------------ |
| Maximum file size                                                | 2 GB                       | fixed                          |
| Total storage for all public files, uploads in progress included | 20 GB                      | `PUBLIC_FILES_MAX_TOTAL_BYTES` |
| Free disk space kept after an upload                             | 2 GB                       | fixed                          |
| Uploads in progress per user                                     | 3                          | fixed                          |
| Storage directory                                                | `/opt/shulkr/public-files` | `PUBLIC_FILES_PATH`            |

An upload left unfinished for 24 hours is discarded.

## What a link can and cannot reach

A link is `/f/` followed by a 256-bit random token, and nothing else: no file name, no number, no path. It opens one file and only that one.

- The token is never stored in clear. The panel looks it up by its SHA-256 hash, and keeps an encrypted copy only to display the link again.
- Files are stored under random names, outside the servers' directories, so neither the file manager, SFTP nor a link can reach one through another.
- An invalid, expired, exhausted, replaced or deleted link always gets the same `404`, so a link cannot be used to learn whether other files exist.
- The type of a file is read from its content, not from its extension. PNG, JPEG, GIF and WebP images are displayed in the browser. Everything else, SVG, HTML and PDF included, is always downloaded, never displayed, so a shared file can never run code on the panel's address.
- Tokens are masked in the panel's logs.

These guarantees protect against someone who only holds a link. They do not protect against code running on the machine itself: Minecraft servers run under the same system user as the panel, so a malicious plugin can read the shared files and their links, as it can read the rest of the panel's data. Nginx access logs also contain the full links. Treat a link as public once you have sent it, and use the expiration, the download limit or a new link to take it back.
